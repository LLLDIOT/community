# 机器学习部分讲解

## 一、这套系统里的机器学习做三件事

1. 计算一份简历与一个招新岗位的相似度。
2. 从简历正文里自动识别技能标签。
3. 把收到的候选人按相似程度分组。

三件事全部使用预训练模型做推理，没有用本系统的数据训练任何模型。

## 二、文字怎样变成向量

使用的模型是 `Xenova/bge-small-zh-v1.5`，主要参数如下：

| 参数 | 取值 |
|---|---|
| 向量维度 | 512 |
| 编码层数 | 4 |
| 注意力头数 | 8 |
| 词表大小 | 21128 |
| 最长输入 | 512 个 token |
| 量化后体积 | 22.9 MB |

模型把一段文字转换成 512 个实数。语义接近的两段文字，转换出的向量方向也接近。

编码前先拼接文本。简历侧按「姓名、学校、专业、年级、技能标签、简历正文」的顺序拼接，岗位侧按「岗位名称、期望技能、岗位要求」拼接。正文截断为 1200 字。技能标签放在正文之前，因为超长输入会从尾部截断。

模型对每个 token 输出一个向量，取首个特殊位置（`[CLS]`）的向量作为整句表示，再做归一化。归一化后向量长度都是 1。

单条短文本编码约 2 毫秒。

## 三、相似度怎样计算

使用余弦相似度，取值含义是两向量夹角的余弦：

```
cos(a, b) = (a · b) / (‖a‖ · ‖b‖)
```

归一化之后长度都是 1，上式简化为点积，计算更快。

这里不用欧几里得距离，因为文本长度会影响向量长度，用距离会把「内容多少」和「语义远近」混在一起。余弦只用方向，不受长度影响。

## 四、为什么必须做校准

实测发现，两段毫不相关的中文，余弦也有 0.46 至 0.52；语义明确相关时最高约 0.75。

| 文本对 | 关系 | 余弦 |
|---|---|---|
| 「精通 Vue」与「会打篮球」 | 无关 | 0.5020 |
| 「喜欢摄影」与「会打篮球」 | 无关 | 0.4691 |
| 「精通 Vue」与「熟悉 Vue3」 | 相关 | 0.7479 |

原因是这类模型输出的向量分布不均匀，任意两向量存在共同方向分量，余弦值被整体抬高。

如果直接把余弦乘 100，无关文本得 47 至 52 分，相关文本得 75 分，所有结果挤在一起，无法区分，也无法设置阈值。

所以做一次线性映射，把 0.46 至 0.75 映射到 0 至 100：

```
分数 = clamp((余弦 − 0.46) / (0.75 − 0.46), 0, 1) × 100
```

映射之后，无关文本得 5 至 9 分，强相关得 88 至 99 分，区分度恢复正常。

这个映射只做等比缩放，不改变任何两项的相对大小，因此不改变排序结果。

参数写在环境变量 `ML_CALIB_MIN` 与 `ML_CALIB_MAX` 中。更换模型后必须重新确定，否则分数会全部挤在两端。

## 五、最终分数怎样得出

```
分数 = 0.6 × 语义分 + 0.4 × 技能命中率        （岗位写了期望技能时）
分数 = 语义分                                （岗位没写期望技能时）
```

技能命中率是岗位期望技能中被简历命中过的比例。

之所以不全部使用语义分，有三个原因：

1. **可以解释。** 招新需要说明为什么推荐某个人。「命中 Vue，缺少 HTML 与 CSS」是可以核对的；一个语义分无法拆解。
2. **同域文本过于相似。** 所有简历都是学生写的简历，语义上天然接近，实测 12 组组合中有 9 组落在 0.52 至 0.62 之间。技能命中率是独立的离散信号，能把人与人拉开。
3. **人工标签更准。** 技能是学生本人填写的，比模型推断可靠。

权重 0.6 与 0.4 是经验取值。因为没有任何标注数据，无法通过数据确定最优值，所以做成环境变量。

排序规则依次是：分数降序、招新中的岗位优先、招满率低的优先。设置后两级是因为分数是整数，大量记录并列，缺少次级排序时结果会随查询顺序变化。

## 六、技能标签怎样自动抽取

抽取值域是一个固定词表，共 92 项。词表的作用是统一命名：`JS`、`javascript`、`JavaScript` 会被归为同一项。

抽取走两条路径：

| 路径 | 方法 | 特点 |
|---|---|---|
| 精确匹配 | 判断正文是否包含词表原词 | 准确，但换一种说法就漏 |
| 语义近邻 | 正文向量与词表向量比余弦，超过 0.62 取前 6 项 | 能识别同义表述，但可能误标 |

两条路径的结果合并，精确匹配优先，并保留每项的来源。实测效果：

| 人工填写 | 自动抽取 |
|---|---|
| 文案、活动组织、沟通 | 活动组织、活动策划、文案写作 |
| 设计、海报、审美 | 海报设计、排版、UI 设计、UX 设计 |
| Vue、Node.js、项目协作 | Vue、Node.js |

第三行说明词表外的技能抽不到（`项目协作` 不在词表里），也说明自动抽取不一定比人工全。

因此抽取结果只写入 `skills_auto` 字段，不修改人工填写的 `skills` 字段。两者在界面上并排显示，来源可以区分。

## 七、候选人怎样分组

使用 K-means，不需要任何标注。

过程是三步循环：选 k 个初始中心、把每个人分到最近的中心、把中心移到该组的平均位置，重复直到不再变化。

初始中心用 K-means++ 选取，按距离平方的概率抽取，避免中心过于集中导致空组。随机种子固定为 42，保证同样的数据每次分组结果相同。

分组数 k 在 2 至 4 之间自动选择，依据是轮廓系数。

轮廓系数衡量「组内是否紧密、组间是否分离」，取值 −1 至 1：

| 取值 | 含义 |
|---|---|
| 0.51 至 1.00 | 分组清晰 |
| 0.26 至 0.50 | 分组较弱 |
| 0.00 至 0.25 | 基本分不出类别 |
| 小于 0 | 分组不当 |

轮廓系数偏低不是程序错误，而是说明这批候选人本身比较同质，分不出明显类别。

人数少于 6 时不执行分组。原因是样本很少时，k 接近人数会出现大量只含一人的组，轮廓系数会虚高到接近 1，此时数值没有意义。

## 八、缓存与故障处理

每个文本只编码一次。编码结果存两级：进程内存和数据库表 `embedding_cache`。

缓存是否有效由文本内容的哈希值判断，内容变了才重新编码。缓存记录里带有模型标识，更换模型后旧向量不会被误用。

如果模型加载失败，或者机器无法下载模型文件，匹配会自动退回字符串匹配算法。此时接口仍然可用，只是分数改成按技能字面命中计算，返回结果中的 `method` 字段会标注为 `tags-only`。

模型在服务启动时异步加载，不阻塞端口监听。

## 九、这套机器学习做不到的事

| 能力 | 状态 | 原因 |
|---|---|---|
| 语义相似度 | 已实现 | 预训练模型推理 |
| 技能抽取 | 已实现 | 词表加相似度 |
| 候选人分组 | 已实现 | 无监督 |
| 录用概率预测 | 未实现 | 没有任何标注数据 |
| 学习排序 | 未实现 | 同上，且现有结论受名额限制，不反映真实偏好 |

另外两点需要注意：

1. 分数不是概率。88 分表示文本语义接近，不表示有 88% 的可能被录用。
2. 输入越短，效果越弱。「前端开发」与「Vue3 页面实现与组件封装」的余弦只有 0.5134，因为缺少上下文。所以文本构造时把多个字段拼成一段，而不是只放几个词。
